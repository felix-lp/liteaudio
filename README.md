# LiteAudio

Аудиоплеер для треков с YouTube, спроектированный вокруг одного ограничения:
**очень медленный и нестабильный интернет (уровень 2G)**.

## Принципы

- **Каждый килобайт сохраняется.** Поток воспроизведения и кеширование — один
  и тот же поток: байты, прочитанные плеером, сразу ложатся на диск и никогда
  не скачиваются повторно.
- **Ровно одно сетевое соединение.** Воспроизведение вытесняет загрузки через
  `PriorityTaskManager`; когда текущий трек добуферизован — канал отдаётся
  предзагрузке следующих треков, затем очереди загрузок.
- **Таймаутов не существует.** Бесконечные повторы с бэкоффом; каждый повтор
  виден в статус-строке с обратным отсчётом.
- **Честность.** Любой процесс, состояние и ошибка отображаются в статус-строке
  сверху. Индикаторы кеша на каждом треке показывают реальные байты.

## Архитектура

| Слой | Что делает |
|---|---|
| `extractor/` | NewPipeExtractor: метаданные, постраничные плейлисты, потоки |
| `media/cache/` | Один `SimpleCache` + `PinningCacheEvictor`: загрузки запинены навсегда, остальное — LRU с настраиваемым лимитом |
| `media/source/` | `liteaudio://` URI → свежая googlevideo-ссылка; ключ кеша `videoId:itag` стабилен при протухании ссылок (403 → переполучение) |
| `media/playback/` | ExoPlayer + MediaSession, очередь Spotify-семантики с персистентностью |
| `media/transfer/` | Планировщик единственного соединения (CacheWriter) |
| `ui/design/` | Собственная дизайн-система на compose.foundation — без Material |

## Сборка

- CI: каждый push собирает debug-APK (Actions → artifacts → `liteaudio-debug-apk`).
- Релиз: тег `v*` собирает подписанный APK и прикладывает к GitHub Release.
- Локально: `./gradlew assembleDebug` (нужен Android SDK 36).

Debug-сборки подписаны закоммиченным CI-ключом — каждый новый APK ставится
поверх предыдущего без переустановки.

## Стек

Kotlin · Jetpack Compose (foundation) · Media3/ExoPlayer · NewPipeExtractor ·
Room · DataStore · OkHttp · Coil. minSdk 29 (Android 10+).
